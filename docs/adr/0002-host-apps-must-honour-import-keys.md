# Host Apps must honour an Import Key and report one outcome per row

Commit is create-only and saves everything it can, then sends the rest to Fix & Retry. When a batch is lost in transit (the server saved it but the response never arrived), its outcome is unknown, and a blind retry would create duplicate records. Every row therefore carries an Import Key generated by Data Weaver, and the Host App's save function must:
- ignore a row whose Import Key it has already saved;
- return one outcome per row: created, or rejected with a reason and, when known, the field.

This makes automatic retries safe, and it lets the Import Report say *why* a row wasn't imported.

## Considered Options

- **No key: show lost batches as "status unknown" and let the Importer check.** Rejected: it hands a non-technical Importer a problem they can't solve.
- **All-or-nothing Commit (transactions across batches).** Rejected: it forces rollback support onto every Host App, and one bad row would block hundreds of good ones.

## Consequences

This is a contract every Host App must implement, and SpeakArt's `csvImportCreateAsset` does not meet it yet:
- It returns only the successful rows (`parsed_row_index`).
- It only counts failures, without reasons.
- One branch `break`s and silently abandons the rest of the request.
- It has no notion of an Import Key.
